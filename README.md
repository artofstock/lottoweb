## 원본에서 그대로 지킨 것

물리 엔진의 상수·수식·연산 순서를 전부 그대로 옮겼습니다. 화면이 60Hz든 120Hz든
물리는 **28ms 고정 스텝**으로만 돕니다 (원본 `FRAME_MS`). 그래야 기기가 달라도
추첨 결과 분포가 흔들리지 않습니다.

헤드리스 300판 실측 — 원본 문서가 적어 둔 페이스와 일치합니다.

| 구멍 | 게임당 평균 | χ²(자유도 44) | 구멍별 분포 |
|---|---|---|---|
| 1 | 43.5초 | 43.0 | 전부 우상 |
| 2 | 22.1초 | 56.1 | 909 / 891 |
| 4 | 12.1초 | 39.4 | 471 / 457 / 454 / 418 |

1·2·4구멍, 비프음 5종, 발표 오버레이 두 방식(고정 간격 / 음성 완료 기반 체인),
TOP 20 통계 오버레이, 자동 진행 카운트다운, 회차·부제, 결과 파일명 규칙까지 그대로입니다.

## 새로 넣은 것

### 조건 필터
제외수 · 고정수 · 홀짝 비율 · 합계 범위 · 연속수 제한 · 구간 쏠림 · 직전 회차 중복.

물리는 손대지 않습니다. 조건에 맞지 않는 **판 전체**를 버리고 다시 굴립니다(기각 표집).
그래서 **조건을 통과하는 모든 조합은 서로 완전히 동등합니다.**

> 다만 조건을 걸면 **번호별 확률은 달라집니다.** 7번을 제외하면 P(7)=0입니다.
> "조건을 걸어도 확률은 똑같다"는 말은 사실이 아니라서, 앱 안에도 그렇게 적어 두었습니다.

버려지는 판은 백그라운드에서 헤드리스로 굴리고, **조건을 통과한 판의 난수 시드**로
화면 물리를 재생합니다. 화면에 보이는 공의 움직임이 실제로 그 번호를 만들어냅니다 — 연출이 아닙니다.
몇 판을 버렸는지는 무대 위 배지에 그대로 표시됩니다.

조건이 모순이거나 너무 빡빡하면 시작 전에 막고, **어떤 조건을 풀어야 하는지**까지 알려줍니다.
통과율 추정은 C(45,6) 전수 열거 참값과 대조해 오차 12% 안쪽임을 확인했습니다.

고정수는 5개까지만 됩니다. 6개를 고정하면 결과가 하나로 정해져 추첨이 아니게 됩니다.

### 내 번호 저장 · 당첨 대조
회차별로 추첨 결과를 저장하고, 실제 당첨번호 6개 + 보너스를 입력하면
1~5등/낙첨을 자동 판정합니다. 맞은 번호는 금테, 보너스는 보라테로 표시됩니다.

동행복권 사이트는 CORS를 막아 브라우저에서 직접 조회할 수 없어 직접 입력 방식입니다.

### 방송 모드 (OBS)
`?broadcast=1` 하나로 조정실이 사라지고 무대만 남습니다. **B** 키로 언제든 전환됩니다.
설정 탭의 [링크 만들기]가 회차·구멍·게임 수·소리·자동시작·투명배경을 URL로 만들어 줍니다.
그 URL을 OBS 브라우저 소스에 넣으면 됩니다.

URL로 넘긴 값은 **저장되지 않습니다.** OBS 링크 한 번 열었다고 평소 설정이 바뀌면 안 되니까요.

### 공정성 셀프테스트
원본은 CLI 전용(`--selftest`)이었습니다. 이제 [검정] 탭에서 워커 여러 개로 돌리고
화면에 리포트가 나옵니다. 2,000게임이 데스크톱에서 약 1.6초.

세 가지 검정을 함께 보여줍니다 — 첫 번째 공 분포 / 당첨 6개 전체 분포 / 구멍별 포획 분포.

| 물리 | 겹친 채 서로 멀어지는 공 쌍은 분리되지 않아 화면에서 파고든 것처럼 보였다 |
| 물리 | 공 45개가 겹친 채 생성돼 시작하자마자 폭발하듯 튕겨나갔다 (겹치지 않는 자리에 놓도록 수정) |
| 통계 | **카이제곱 검정이 4.5배 관대했다** — 아래 참조 |

### 카이제곱 보정

원본은 "당첨번호 6개 전체" 도수에 자유도 44 카이제곱을 그대로 적용했습니다.
한 게임에서 6개를 중복 없이 뽑으므로 번호끼리 음의 상관이 있어, 통계량의 귀무 기댓값은
44가 아니라 **39**입니다. 즉 원본 검정은 항상 관대한 쪽으로 틀려서 실제 편향이 있어도 놓칠 수 있었습니다.

45개 중 6개를 비복원 추출할 때 X² ≈ ((45−6)/(45−1))·χ²₄₄ 이므로 **44/39배 보정**하면 정확해집니다.
이상적 균등 추첨 2,000회 × 2,000게임으로 검증했습니다.

| | 평균 | α=0.05 기각률 | p-value 균등성 |
|---|---|---|---|
| 원본 방식 | 39.01 | 1.10% | — |
| 보정 후 | 44.01 | **5.00%** | KS 0.014 (통과) |

p-value도 Wilson–Hilferty 근사 대신 불완전감마함수로 직접 계산합니다 (오차 ~1e-4).

## UI 개선

**무대 / 조정실 분리** — 무대는 시청자가 봐야 하는 전부(회차·캔버스·슬롯·오버레이),
조정실은 운영자만 필요한 전부. 방송 모드는 조정실을 숨기는 것이 전부라 조작 UI가 새어 나갈 여지가 없습니다.

- 반응형: 1920×1080 방송 화면부터 375px 폰 세로까지
- 슬롯 아래 실시간 조합 요약 (합계 · 홀짝 · 최대연속 · 끝수합), 조건 위반은 빨갛게
- 공은 스프라이트로 미리 그려 두고 매 프레임 `drawImage`만 (중급 폰 대응)
- 물리 28ms 사이를 보간해 화면 주사율로 부드럽게 (물리 결과는 불변)
- 밝은 테마 (무대는 어두운 채로 유지 — 공 색이 어두운 배경 전제라서)
- 단축키 Space / R / S / T / H / B, 키보드 포커스 표시
- 설정·기록은 localStorage, `.txt` / `.csv`(엑셀용) / 전체 백업 `.json` 내보내기

## 알려진 제약

- **로컬에서 `index.html`을 더블클릭하면** 크롬이 Blob 워커를 막습니다. 조건 탐색과
  셀프테스트가 한 스레드로 폴백하며(느림) 화면에 안내가 뜹니다. 웹에 올리면 정상입니다.
- **음성안내**는 브라우저에 한국어 음성이 있어야 합니다. 없으면 버튼이 비활성화됩니다.
  (Windows는 Microsoft Heami 등이 기본 설치)
- **브라우저는 사용자가 한 번 클릭하기 전에는 소리를 내주지 않습니다.** 화면 아무 곳이나
  한 번 누르면 풀립니다. OBS에서는 소스 속성의 "페이지가 보이지 않을 때 소스 종료"를 끄세요.
- **기록은 이 브라우저에만 저장됩니다.** 방문 기록을 지우면 함께 사라지니 가끔 백업하세요.
- 원본의 `lotto_template.xlsx` 기반 엑셀 자동 생성은 뺐습니다. 외부 라이브러리 없이
  재현할 수 없고, CSV면 엑셀이 그대로 엽니다.
- 이 앱은 실제 로또 당첨을 예측하지 않습니다.
